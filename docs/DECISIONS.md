# 明确事项与设计边界 (Decisions & Non-Goals)

本文档记录本项目（南湖／文昌校园网守护程序）中**已明确敲定、具备不可变性（Immutable）的核心设计原则、功能边界与明确不做的事项（Non-Goals）**。

后续任何功能建议、代码审查或架构调整均以此文档为红线，**禁止反复讨论或提出与已决事项冲突的需求**。

---

## 一、 明确不做的事项（Non-Goals）

### 1. 绝对不做多账号管理与切换
- **结论**：本软件**绝对不做多账号管理、多账号预设、多账号快速切换或多用户配置隔离**。此决策为终局决策，后续任何版本均不再考虑，禁止再提。
- **依据与定位**：
  1. **产品定位**：本工具是针对个人 PC、宿舍/实验室主力设备的**单机、单用户、无人值守轻量级后台守护程序**，核心使命是网络断开时自动、无感恢复外网。
  2. **系统复杂度**：多账号管理会剧烈推高凭据存储拓扑（Windows DPAPI 结构）、配置合并逻辑、IPC 协议以及 UI 交互状态的复杂度，与“低资源占用、轻量、高可靠”的设计初衷背道而驰。
  3. **替代方案**：若用户因套餐或运营商变更需要使用新账号，直接在“账号设置”面板输入新账号/密码并保存即可覆盖原配置。

## 二、 架构与安全红线（Architectural Red Lines）

### 2. 凭据安全单向写入原则（Write-Only）
- **结论**：已保存密码在前端 UI、DOM、IPC RPC 层面**永久只写不读**，绝不回显。
- **规则**：
  1. 后端 `getConfig` RPC 仅向前端返回 `hasPassword: bool`，绝对禁止向前端暴露明文密码或解密后密文。
  2. 前端密码输入框留空表示保持当前已保存密码不变；只有在输入新内容时才向后端提交更新。
  3. 前端界面严禁增加密码明文查看按钮（如“眼睛”图标），防范肩窥与界面注入风险。

### 3. 系统网络配置零侵入原则（Zero-Touch OS Config）
- **结论**：绝对不破坏、篡改或覆盖操作系统原生的网络连接与无线 Profile。
- **规则**：
  1. 程序仅在“有线网络不可用且无线网卡处于未连接状态”时，通过 Windows WLAN API 请求连接系统已存的 `CUMT_Stu` 配置。
  2. 若用户已主动连接其他网络（如手机热点、客用 Wi-Fi），程序绝不主动切断或强行切回校园网。
  3. 绝不修改系统无线配置文件的密码/加密方式，不篡改网卡驱动高级属性。

### 4. 故障安全与原子持久化原则（Atomic Persistence）
- **结论**：配置文件更新必须具备事务级故障安全性，严防半写入损坏。
- **规则**：
  1. 配置写入必须严格走“写入临时文件（`0700`） -> `FlushFileBuffers` (`Sync()`) 刷盘 -> `os.Rename` 原子替换”的标准流程。
  2. 发生写入冲突（如杀软占用导致 Sharing Violation）或系统断电时，绝不能损坏原有的合法配置文件。

### 5. 耗时 I/O 锁外执行原则（Lock Decoupling）
- **结论**：状态互斥锁仅保护内存关键区，严禁持有锁执行重度 I/O。
- **规则**：
  1. 包含 DPAPI 加解密、文件磁盘落盘（`FlushFileBuffers`）、网络 HTTP 探测与 DNS 解析等耗时 I/O 操作，**一律不得在全局状态锁（如 `c.mu`）内执行**。
  2. 严防死锁与 UI 卡顿，确保主事件循环与托盘 UI 线程的极低响应延迟。
