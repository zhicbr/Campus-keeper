## 一、 核心功能与稳定性改进（来自 11-01 事故复盘）

### 1. **Win32 托盘生命周期与交互自愈**
- [x] **监听 `TaskbarCreated`**：通过 `RegisterWindowMessageW("TaskbarCreated")` 捕获资源管理器（`explorer.exe`）重启消息，自动重绘系统托盘图标，彻底杜绝“幽灵后台”。
- [x] **单实例唤醒自愈**：在接收到 `WakeMessage`（用户双击 exe 唤起已有实例）时，主动核验并补加托盘图标。
- [x] **设置/日志窗口显式退出入口**：在前端面板增加“退出程序”按钮，避免在托盘失联时用户缺乏交互出口。

### 2. **Wi-Fi 震荡与漫游防抖（核心网络循环）**
- [x] **60 秒连接保护期**：网卡连接状态切换初期，设立 60 秒纯只读静默期，严禁触发主动断开或重连。
- [x] **主动 Ping 探测**：在判定网关无响应前，通过轻量 UDP/ICMP 探测主动唤醒操作系统 ARP 缓存，杜绝消极误判。
- [x] **放宽 `DeadGatewayThreshold`**：门限由激进的 2 次调宽至 6 次（30 秒以上）。
- [x] **漫游熔断机制**：连续漫游重试达到 2 次后，触发熔断停机，停止一切主动断开重连行为，保留网卡连接以防网络震荡。
- [x] **外网 DNS 故障直通**：当外网 DNS 无法解析、无法捕获 302 重定向时，针对校内核心认证页 `http://10.2.5.251/a79.htm` 主动发起直连探活并完成登录。

### 3. **日志淘汰与清理机制**
- [ ] 支持轮转日志自动生命周期管理与最大配额压缩。

## 二、 架构与代码质量

### 1. **控制器“上帝对象”拆分**
- 控制器承担了过多链路检测、Wi-Fi 操作、重试定时器与 UI 调度职责，需进一步拆分出独立的网络链路管理器与状态机。

### 2. **核心网络循环“不可 Mock”问题**
- `internal/network/` 直接硬编码调用了 Windows 系统 API（`GetAdaptersAddresses`、`wlanapi.dll`），需抽象出标准接口（如 `NetworkInterfaceProvider`、`WlanManager`），支持在单测脱机环境下模拟“网线拔出”、“漫游断开”、“DHCP 延迟”等边缘异常流。

### 3. **状态管理形式化状态机（FSM）**
- 显式定义 `State` 状态流转转移矩阵，消除散落在多个布尔值与离散时间戳中的隐式状态。

### 4. **前端资源嵌入**
- 使用 Go 1.16+ `go:embed` 替代大文本 Go 字符串。
